## 批量化阻碍清单（T45 前必须处理）

优先级 P0 = 不做就无法批量；P1 = 能跑但会拖慢/返工；P2 = 质量或效率改进。

1. **P0 验收器把“盾 + 剑”写死。** `validate.py` 的 `validate_spec_model` 断言 `shield_rim`、`shield_front`、盾径；`validate_chibi_poses` 直接读 `sword_blade`；`validate_shield_poses` 要求盾面和盾后可见性。T45 只要有弓手、长矛、无盾单位就会失败。  
   最小修法：规格增加 `equipment: [shield, sword]` 或能力描述，验收器按装备能力分派检查；没有剑就不要跑剑刃射线，没有盾就跳过盾面角度/遮挡。负责：Codex（验收器跨类型改造）。

2. **P0 16 个部位分区必须全部出现在网格里。** `validate.py:89` 的 `set(ob['part'] for ob in OBJECTS) == set(PARTS)` 要求 skin/helmet/tunic/…/belt_buckle 全部有几何。本件没有头盔，只能把下颌映射到 `helmet` 区、牙缝画在 helmet 贴图上，才凑满 16 区。无盾/无盔的正式兵种会被迫造“假部件”。  
   最小修法：给规格加 `used_parts` 或允许 `unused_parts`，验收从“必须全用”改成“声明的分区必须用、未声明的分区贴图保持空白”。负责：Codex + Lead 定契约。

3. **P0 纯侧视脸不可见。** 共享头部 UV 只在 +X 正面楔形画脸；侧视镜头下脸只有一两个像素。k2 靠头盔和大眼线还能读，骷髅/新兵种会被加成“白蛋”。本件用额外扁盘眼窝绕过，不是通用方案。  
   最小修法二选一：(a) 给头部 UV 增加“侧面投影”通道，把近侧脸画到 -Y 面；(b) 每个头型配独立的侧面贴片/几何。需要 Lead 定美术方向，Codex 实现。负责：Claude/Lead 定方向，Codex 实现。

4. **P1 新兵种要写 Python 配方和探针。** `build_shieldman.from_spec` 只认识 `recipe: e2e_grunt`；`proportion_probes`、`sword_obstacles`、`face_full_head` 都是配方属性。换武器/换头型必须新增 `build_*.py` 并在路由里加分支。  
   最小修法：建立 `recipe` 注册表 + 组件（头型、武器、盾型、披风）组合，规格只选组件和参数；至少把 e2e 的探针命名约定写进 `docs/sprite-pipeline.md`（本轮 docs/ 禁止改，交给 Lead/Codex）。

5. **P1 默认验收列表硬编码。** `validate.py:404-409` 写死 T06、k2、e2e；T45 有 N 个兵种时每加一个都要改代码，`verify.sh sprites` 也会线性变慢。  
   最小修法：`assets/specs/manifest.yml` 或 `assets/sprites/*/` 发现规则；默认验收读清单，`--spec` 仍可单件跑。负责：Codex。

6. **P1 没有快速模式。** 构建 24.11s 中约 17s 花在 5 张 768×768 普通着色视图（front/side/back/equipped/equipped_side），69 帧数据图集约 5s。T45 迭代时每改一次头型都重渲 5 张视图很浪费。  
   最小修法：`render_sprites.py --skip-views` / `--views none|final`；批量迭代只出图集+JSON，首件/末件再出视图。负责：DSH 或 Codex，工作量小。

7. **P1 Godot 截图不能真正无人值守。** 窗口模式可用（13.97s/次），但 headless 没有渲染视口；`capture.gd` 现在明确 `quit(2)`。而且脚本前缀、帧表（14 帧）写死，每换一个兵种要改常量。  
   最小复现：`godot --headless --path . -s assets/sprites/e2e/capture.gd` → 退出 2，无 PNG。窗口模式 `godot --path . -s assets/sprites/e2e/capture.gd` → 两张 1600×700。  
   最小修法：做参数化 `capture.gd <asset_id> <frame_spec>`，并确认 CI/谷时任务是否有桌面会话；没有就转 Codex 做离屏渲染。负责：Codex（引擎/渲染问题）。

8. **P1 游戏接入口只认 k2_shieldman。** `scripts/main.gd:_setup_assets` 只调用 `_load_blender_sprites("k2_shieldman")`；函数本身能接受带斜杠的 id，但注册和 `stats["sprite"]` 路由没有批量入口。本轮禁止改 scripts/，所以 e2e 只能独立脚本加载。T45 正式接入必须改 `main.gd`（或把加载表数据化）。负责：Codex/Lead，T44/T45 一起做。

9. **P2 身高和相机固定。** `ChibiBody(..., height=1.92)` 不从 spec 读身高；`render_sprites.setup_scene` 固定 `ortho_scale=3.05`、中心高 1.465；JSON 的脚底锚点按 64px 固定。T45 如果要轻重/大小兵种，需要规格字段和逐件相机，否则高个子会顶格、矮个子浪费空间。负责：Codex。

10. **P2 面部/纹章绘制是 Python 代码，不是数据。** `paint_tile` 里 `if look['skull']` 画眼窝/鼻腔/牙；新增脸型、面纹、盾徽都要改 Python。T45 批量 16 个兵种会很快把这里堆成 if/else。  
    最小修法：把面部/盾徽拆成小型绘制函数注册表，规格按名字选；或生成独立的 256 图块素材。负责：Codex/DSH。

11. **P2 截图没有自动质量门。** `e2e_pipeline.py` 只检查进程退出码；首轮接触表全空也能 exit 0。需要至少检查 PNG 尺寸、非空像素比例、调色板/部位数，或对比一张基准图。负责：DSH（T63 美术资产检查工具已有基础，可复用）。

12. **P2 Godot `user://logs` 报错。** 每次运行打印 `Failed to open 'user://logs/...'`，不影响截图，但日志噪音会掩盖真实错误。可用 `--user-data-dir` 或项目设置修。负责：DSH。
