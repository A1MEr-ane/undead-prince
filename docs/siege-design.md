# 攻城玩法：可行性与实现难度评估（Claude，2026-11-26）

评估对象：`docs/gameplay-discussion-2026-11-26.md`（用户与另一模型的玩法讨论交接）。下文称"新方案"。
对照的依据有三类：
- 现有代码：`scripts/`，约 3900 行
- 现有设计：`docs/roguelike.md`、`docs/boons.md`、`docs/units.md`、`docs/canon/`
- 测试数据：T61 性能表、T49 守军扫描

标注：【用户】= 讨论里用户明确提出；【议】= Claude 的判断和建议；"未验证" = 没有原型数据支撑。

## 0. 结论
- **可行，方向对**。新方案修正了现有原型最大的问题：Bad North 式小岛加固定小队，打起来只是"把两队人推到旗下"，没有进攻方该有的决策空间。
- 新方案的核心是"用冥火原子化部署 + 单位自主作战 + 守军有组织地跨区支援 + 夜晚倒计时"。这一套能自然产生侦察、牵制、突破、总攻的节奏，而且操作负担低。
- **最大的风险不在美术，在玩法验证和 AI**。有三件事都要靠原型才能回答，纸面推不出来：
  - 自主单位的行为玩家能否读懂、能否预期
  - 守军支援的时间差能否被玩家利用
  - 冥火曲线会不会导致"挂机等最后一分钟"
- **程序难度：中等偏高**，集中在三处：大地图上大量自主单位的寻路和索敌、守军调度、城墙状态改变通行。现有代码能复用的比例不低，见第 3 节。
- **美术难度：中等**。地图变大，但模块化方案（`docs/research/FLEET_ART_TECH_DECISION.md` 第 5 节）已经覆盖。新增的主要是夜间光照和破晓变化、更多兵种精灵、城墙的破损状态。都不需要新技术。
- **世界观要做两处适配**（第 4 节）：
  - "只能在夜晚作战"和王都永昼的关系
  - 原子化部署取代"旧部小队跨局保留"
  这两处适配都能让剧情更好，但要你拍板，因为 canon 只读。

## 1. 逐项可行性
| 机制 | 判断 | 理由与风险 |
|---|---|---|
| 冥火原子化部署，长按连放【用户】 | 可行，推荐 | 操作负担最低，也最契合"灵魂力量化为军队"的设定。风险：单位多了画面会乱，需要阵营光色和部署落点预览帮助读图 |
| 单位自主行动（攻击偏好加基础行为）【用户】 | 可行，关键风险点 | 现有剑兵大脑（备战、冲锋传播、威慑）本身就是自主的，可以复用。新增的是**目标选择**：按兵种偏好选高地、城门、弓兵、最近敌人。风险是全军涌向同一个路口。需要"分流"规则，例如部署点决定初始目标、拥堵时改道 |
| 冥火随时间回复，有储存上限【用户】 | 可行，推荐作为默认 | 能自然形成一波一波的进攻，失败后也能重整。击杀收益建议改为增益方向（见 §2 招魂），不进基础规则【议】 |
| 夜晚 5 分钟，黎明前最强【用户】 | 可行，需原型调曲线 | 主要风险是"挂机等最后一分钟"。缓解办法【议】：<br>1. 早期战果持续有效：守军伤亡不补满，城墙破口不修复，被刺杀的军官不复活<br>2. 守军也随时间加强：天快亮时王国增援抵达<br>3. 冥火上限不随时间提高，提高的是回复速度和亡灵属性，所以后期仍要分批投入 |
| 守军：兵种职责、阵地、跨区支援（借鉴 Bad North 调度）【用户】 | 可行，难度最高 | 现有 `squad.gd` 能做"小队移动到据点、站位、到位转身"，T49 已经做了 0.5 秒联动。缺的是**全局调度层**：哪个据点受威胁、派谁去、留多少驻防。规则要可预测，玩家才能利用：固定的感知半径、派兵延迟、最低驻防人数 |
| 地形无血量，城墙和城门可改变【用户】 | 可行，对工程友好 | 自然地形不可破坏省掉大量物理和网格工作。城墙只做几个预设状态：完好、破口、城门开或关；状态切换时重算该区域的流场。现有地形是网格加流场，改起来便宜 |
| 大路、小路、山洞【用户】 | 可行 | 道路就是可通行宽度，不加属性。山洞是寻路网格上的一条"传送边"，流场算法天然支持 |
| 地图扩大：多轴线、多战区、防御纵深【用户】 | 可行，生产成本是主要压力 | 和已有的"蓝图 + 地区套件 + 地标"方案一致。先手工搭 2–3 张战术拓扑图验证玩法，再考虑程序生成 |
| 肉鸽四方向：整体战力、冥火、指挥、兵种；渡魂人改规则【用户】 | 可行，和已定的"五位旧部给增益"天然对上 | 见 §2 |

## 2. 与现有设计的对照
| 现有设计 | 新方案 | 处理【议】 |
|---|---|---|
| 旧部五人给增益（已定） | 四个强化方向，渡魂人改规则 | 一一对应：<br>伯纳德 → 整体战力与前排（坦克回血、不屈）<br>奥斯温 → 冥火经济与法术<br>皮普 → 指挥与调度（号令、狂化、虚弱）<br>玛蒂尔达 → 特定兵种质变（缝合巨人、复生、"轮椅"构筑）<br>渡魂人 → 规则级馈赠（例如"开局冥火加倍但不再自然回复"）<br>`docs/boons.md` 的槽位要改写：原来的槽位绑定"刃、阵、行军"等动作，改成绑定冥火、法术、兵种 |
| 招魂：尸体变亡魂 | 击杀收益未定 | 把"击杀收益"做成**招魂**：杀死的守军留下尸体，招魂类增益把尸体变成免费单位或冥火。既回答了击杀收益的去留，又是亡灵题材的爽点 |
| 部队跨局保留、整队覆灭就失去（roguelike.md §2） | 不预设兵力，每场用冥火生成 | 改为：跨局保留的是**已解锁的兵种和它们的强化**，士兵本身每场重新生成。"招募"奖励改成"解锁兵种或给兵种升级" |
| 每局 6–9 场战斗 | 每场 5 分钟加部署观察 | 每场 6–8 分钟，9 场约一小时，偏长。建议每局 5–7 场，加剧情地点 |
| 小岛地图、3D 地形加精灵 | 大地图、城墙、多战区 | 渲染方案不变，地图按三档尺度做 |
| 王子是英雄单位 | 未提 | 建议王子不作为单位上场，冥火就是他的力量；王子倒下判负的规则改为"天亮前没攻下目标就失败" |

## 3. 程序实现难度（依据现有代码和 T61 实测）
| 模块 | 现状 | 要做的 | 难度 |
|---|---|---|---|
| 单位战斗行为 | 剑兵大脑完整：拼刀、格挡、击倒、落水、冲锋传播 | 按兵种扩展：远程、攻城、潜行、法师 | 中 |
| 目标选择与分流 | 只有"走向小队站位" | 新写攻击偏好、目标评分、拥堵改道 | **中高** |
| 寻路 | 网格流场，按目标缓存 | 多目标流场、城墙状态改变时局部重算、山洞传送边；大地图要分块 | 中 |
| 守军调度 | 小队协调器，加 T49 的联动 | 全局调度层：威胁评估、派兵、驻防下限、延迟 | **高** |
| 冥火经济、时间、法术 | 无 | 计时、回复曲线、部署 UI（长按连放、落点预览） | 低到中 |
| 性能 | 200 个单位约 7 毫秒/帧（无头逻辑，T61） | 300 个左右可以直接承受；500 个以上需要降低远处单位的思考频率、合批渲染（MultiMesh）、按区域查询敌人 | 中 |
| 平衡工具 | 有：批量模拟、确定性、异常检测（T60、T23） | 加冥火曲线和守军参数的扫描 | 低 |

- 总量估计：把可玩原型做到"能判断好不好玩"，大约需要 Codex 2–3 个大工作包，加 DSH 的批量测试。
- 现有代码中，地形、流场、精灵和单位物理基本都能复用。主要新写的是目标选择和守军调度。

## 4. 美术实现难度
| 项目 | 难度 | 说明 |
|---|---|---|
| 大地图与要塞 | 中 | 模块网格加地区套件加地标，已有方案。城墙需要 2–3 个状态版本（完好、破口），不做实时破碎 |
| 夜间与破晓 | 低到中 | 加分项：用光照讲时间。冥火青绿是夜里最亮的颜色，天边从墨蓝渐渐变成鱼肚白，同时就是倒计时，可以少一个 UI 计时器。现有天光体积可以烘焙"夜"和"晨"两套，按进度混合 |
| 兵种精灵 | 中 | 亡魂 8 种加王国 8 种，管线已经跑通（T64），批量前还要修 12 个问题 |
| 法术与攻城特效 | 中 | 按 FLEET_ART_TECH_DECISION 第 2 节的四类做 |
| 读图性 | 中，关键 | 几百个自主单位同屏时，玩家要一眼看出战线在哪、哪里缺口、援军从哪来。需要阵营光色、守军调度路线的提示（例如援军举火把）、城墙破口高亮 |

## 5. 世界观适配（需要你决定，canon 只读）
1. **为什么只能在夜晚作战**【议】：残余冥火只在没有日光时能凝成实体。破晓时契约的"收潮"把亡灵召回海里。
   - 这和 canon 里"契约在收潮时召回王子"同一个原理，只是把收潮从"一轮远征结束"细化到"每个夜晚结束"。
2. **王都永昼**【议】：王都没有夜晚，所以王都战是唯一不能等天黑的仗。王都战有两个方案：
   - 方案一：冥火不自然回复，只能靠招魂。
   - 方案二：先拿下秘印相关的地点，让王都局部变暗。
   这正好把"终止永昼"从结局选择变成了玩法体验，终止永昼的结局里也第一次出现真正的黄昏。
3. **军团的构成**：canon 说军团是"旧部 + 被征来的士兵"。原子化生成可以解释为"冥火让应召的亡魂成形"，这和 canon 里"普通招魂用残余冥火"的说法一致。旧部五人不上战场，留在沉钟湾，以增益的方式出力。

## 6. 建议的下一步：两个原型，先验证好不好玩
1. **原型 A：灰盒攻城**（Codex）
   - 一张手工搭的中型地图：海岸登陆、外城墙加城门、两条路（一条大路、一条小路）、高地弓兵阵地、主堡。
   - 只有一种亡魂、三种守军，冥火部署（长按连放），自然回复加上限，5 分钟夜晚倒计时，守军跨区支援（带延迟和驻防下限）。
   - 不要美术，不要增益。
   - 验证：至少三种不同的进攻路线都能赢；早期战果有持续价值；不会出现"挂机最优"；自主单位的行为可读。
2. **原型 B：构筑质变**（原型 A 成立之后）
   - 加 3–4 个兵种和 10 个增益，验证"前期混编、后期专精"是否成立，以及"轮椅"构筑够不够爽。
3. **数据**：DSH 用批量模拟跑冥火曲线和守军参数的组合，产出"挂机收益""早攻收益"对比表。

暂不做：正式数值、程序生成地图、美术资产。
