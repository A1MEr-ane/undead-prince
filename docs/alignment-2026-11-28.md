# 玩法、美术、程序三线对齐（2026-11-28）

- 起因：用户指出 Claude 过于冒进，没弄清需求就开工；玩法、美术、程序互相关联，应先对齐三者的进度，再做整体规划。
- 本文只陈述现状、依赖关系和待决事项，不派新任务。
- 已暂停 T82（小兵形象与 Blender 管线）。它依赖兵种清单、镜头和局内画面，这三样都还没定。
- T80（行为场景测试）和 T81（行动逻辑修正）继续跑。理由：用户已经明确"现阶段只需要解决行动逻辑"，这两个任务只改攻城原型。

## 1. 三条线的现状（事实）
### 玩法
| 已定 | 已做出来、但用户没亲手验收 | 未定 |
|---|---|---|
| 冥火原子化部署；夜战 5 分钟；两种胜利（全歼、攻占后守军撤离）；自然地形不可破坏；城墙可破；守军跨区支援；四个强化方向加渡魂人馈赠；只解决行动逻辑，不测胜率 | 灰盒攻城原型（T67/T69/T74）：部署、冥火、守军调度、刺客、巨人、破墙、山洞；战区固定视角原型（T70） | 镜头方案；击杀收益；部署区是否扩展；攻城失败的后果；第一批正式兵种；地图是否重新设计；冥火曲线 |

**最大的缺口**：核心玩法还没有经过用户亲手试玩并给出判断。自动数据只能看出 bug，看不出好不好玩。

### 美术
| 已定 | 已产出 | 缺口 |
|---|---|---|
| 立绘：精炼墨线；结局：史诗厚涂、不放文字；UI 原则（克制、细金线、三种转场）；局内：3D 地形加朝向镜头的精灵、墨线、阵营边光 | 15 个人物立绘；9 张结局图（E06 不合格）；8 张剧情插画；设定集；Q 版兵种阵容图（2D 概念） | **局内画面从来没在引擎里按目标风格做过**。玩家 90% 的时间看的是战场，而目前战场只有灰盒色块，以及最早那版 Bad North 式的盾兵精灵 |

### 程序
| 部分 | 状态 |
|---|---|
| 主工程 `scripts/` | Bad North 式的"小队加点地下令"战斗（旧操作模型），加上远征航图、回溯、结局框架（T28/T29） |
| 攻城原型 `proto/siege/` | 新玩法模型（原子化部署、自主单位、守军调度），灰盒画面，独立于主工程 |
| UI 动效原型 `proto/ui_motion/` | 占位图形，等用户试手感 |

**结构问题**：新玩法写在原型里，主工程的战斗还是旧模型，两套代码在分叉。迟早要决定原型怎么并入主工程。

## 2. 三者之间的依赖
```
镜头方案 ──┬─> 战场地图怎么设计（每个战区怎么构图）──> 地形和建筑美术
           └─> 小兵要几个方向的精灵 ──> 精灵管线和工作量
兵种清单 ──┬─> 行动逻辑（每个兵种的行为）
           ├─> 动作清单 ──> 精灵管线 ──> DSH 批量建模
           └─> 守军构成和地图上的阵地
战场规模 ──> 同屏单位数 ──> 性能 ──> 精灵和特效的预算
冥火经济、部署规则 ──> 部署 UI 和 HUD
世界观（夜战、永昼） ──> 局内光照（夜色、黎明、王都的人造光）
```
结论：**镜头**和**兵种清单**是两个上游决定。它们不定，地图、美术、精灵管线都会白做。

## 3. 建议：用一个"纵切片"把三条线对齐【议】
纵切片指的是：一张战场，从头到尾做到接近成品的样子，用它同时检验玩法、美术、程序。
- **范围**：
  - 1 张中型战场，3–4 个战区。
  - 亡灵 3 种：普通亡魂，加两种功能兵种。
  - 守军 3 种：盾、弓、骑。
  - 一夜 5 分钟。
  - 最基本的部署 UI 和 HUD。
- **玩法**：行动逻辑通过 B01–B12 场景测试；用户试玩，判断"好不好玩、看不看得懂"。
- **美术**：
  - 局内画面按目标风格：墨线小兵、阵营边光、暗调地形、夜到黎明的光照。
  - 只做这张图需要的模块和 6 个兵种。
- **程序**：
  - 决定原型怎么并入主工程。
  - 性能在这张图的规模下达标。

## 4. 决策顺序（每一步都由用户确认后才往下走）
| 关口 | 需要用户做什么 | 它决定什么 |
|---|---|---|
| G1 | 试玩现在的攻城原型（战区视角版，约 15 分钟），按第 5 节的问题给出感受 | 核心玩法保留、调整还是推翻 |
| G2 | 选镜头：战区固定视角，或自由旋转 | 地图怎么设计、精灵要几个方向 |
| G3 | 定纵切片的兵种：亡灵 3 种、守军 3 种 | 行动逻辑、动作、精灵的范围 |
| G4 | 验收一张**引擎里的**局内风格样张：Codex 用占位精灵把一个战区做成目标画风 | 局内美术方向，之后才开始批量做精灵和地形 |
| G5 | 定原型和主工程的合并方式 | 后续程序结构 |

G1–G3 都确认之后，才恢复 T82（精灵管线）和 DSH 的批量建模。

2. 打完第一波，会不会改变你第二波的计划？

4. 等冥火的时候，是在想下一步，还是在干等？
5. 输了，知道为什么输吗？
6. 战区固定视角，切来切去累不累？有没有漏看什么？
7. 刺客、巨人（按 README 里的开关打开）有没有改变你的打法？

## 6. 用户决定（2026-11-28）
- **G1 通过**：灰盒原型"还挺好玩"。临场感、爽快感、指挥调度、构筑快感要等加上美术和肉鸽成长后才能判断。
- **G2 镜头【定】**：局内只用**单个战区的固定视角**，在地图界面上切换战区。自由旋转方案作废。
- **G3 亡灵兵种（部分）【定】**：缝合巨人、暗影刺客、普通骷髅、巫妖四种确定。兵种表不是终稿。具体能力定位和肉鸽构筑路径留到下一步设计。
- **下一步方向【定】**：先从基础单局做起。
- 单局的具体范围、守军兵种、四个兵种的能力由谁先设计、代码怎么合并，都在等用户确认（见下方问题）。
- 用户确认（问答）：单局先做"规则 + 局内美术"；守军用盾兵、弓兵、骑兵；兵种能力由 Claude 起草、用户审阅；代码在仓库里作为独立的尝试版 demo 来做，和原路径分开，以后再考虑合并。草案见 `docs/single-battle-v1.md`。
- 【定】2026-11-28 用户：局内风格样张（T84）通过，开始生产。样张的已知不足（夜晚偏亮、冥火不够突出、地形边缘墨线略粗）在生产中修正。
- 【定】2026-11-28 用户："改成丧尸吧"。普通骷髅改为**普通丧尸**。定位、费用、行为不变；标志能力"骨堆重组"改为"残躯再起"（倒地 4 秒内附近无敌人就爬起，限一次），数值和规则不变。起因：连体下半身做在骷髅上像穿长裙，骨架感出不来；丧尸有肉身，连体裤腿更自然。

## 7. 首次试玩单局后的反馈（2026-11-29，用户原话整理）
> "地图要改成整体视角，然后可以局部放大。像部落冲突一样。设计部署的边线而不是一块区域。UI 还非常简陋，可以后面再实现，但是小兵没有立体感，动作也很僵硬。逻辑非常呆板，杀死敌人和攻破城门的反馈很弱。另外整体美术太简陋了。"

- **镜头【定】**：改成**整张地图的整体视角，可以局部放大**（参考部落冲突）。它取代 G2 的"单战区固定视角加地图界面切换"。
- **部署【定】**：改成**沿边线部署**，不再用一块部署区。
- **UI**：现在简陋，后面再做。
- **待解决的问题**（方向等用户确认，见下面）：
  1. 小兵没有立体感，动作僵硬。
  2. 行动逻辑呆板。
  3. 击杀和破门的反馈弱。
  4. 整体美术简陋。
- **冲突提示**：AGENTS.md 里"局内战斗与建模以 Bad North 为模板"是之前的【定】。改成整体视角加缩放以后，镜头和部署都偏向部落冲突。小兵如果改用 3D 模型，建模也会离开 Bad North 的做法。这条是否改写，等用户确认。

### 用户确认（2026-11-29 问答）
- **小兵【定】**：改用**实时 3D 低模加卡通着色**，用骨骼动画。原因是整体视角加缩放下，单侧面精灵要么糊要么太小，而且只有一个侧面会显得扁。
  - 后果：T82、T87、T88 的精灵管线和 7 套图集不再是正式方案。资产保留作参考，造型设计（比例、连体下半身、配色、兵种剪影）沿用到 3D 模型。
  - 要先做样张（1–2 个兵种，加同屏数量的性能测试），通过后再批量生产。
- **先后顺序【定】**：先做**整体视角、缩放和边线部署**，其余排在后面。
- **逻辑呆板的具体所指**（用户原话）："移动速度和碰撞体积的差异，巨人在前面扛着丧尸要有蜂拥而上的感觉，兵种特色不明显。"
- **美术简陋的范围**：地形和建筑、光影和氛围、特效、小兵本身，四项都要改。
- **Bad North 模板**：局内的镜头、部署和建模不再以 Bad North 为模板。镜头和部署参考部落冲突，小兵用实时 3D。行动逻辑里已经验证过的部分（节拍、冲击、击退）保留。
