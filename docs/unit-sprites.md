# 基础单局小兵精灵【议】

适用范围为《基础单局 v1》第 2 节的七个兵种。设计以通过的 T84 午夜局内样张为准，Q 版阵容图用于参考骨相和装备。当前分支的样张和单局规格可从 `main` 对照读取。本文的轮廓、动作素材和播放时序交 Lead 审批，战斗判定沿用单局规格。

## 1. 公共造型【议】

- 单战区固定镜头。模型朝 +X，Blender 相机在 −Y 纯侧正交。游戏镜头俯角 30°，画面向左时水平翻转。发射点、阵营光和处于前后的装备一起翻转。镜头侧的眼窝、眉线或兜帽开口直接投影到头部 UV。
- 人形保持 B 比例。头含盔约占身高 44%，腿含脚约 22%，脚短圆。巨人以原比例放大并用肩甲、前臂外形做横向体量。骑兵上半身沿用人形比例，以马颈、马身和四蹄扩大轮廓。
- 以 720p 画高下普通步兵站姿约 48 px 为读图基准。每个兵种保留 3–4 组大色，墨线约 1–2 屏幕像素。明暗分成两档。亡灵用青绿边光，守军用暖金边光。眼窝、衣缝和墨线共用深色组。夜里青绿可辨，冥火弹和眩晕特效仍占画面最高亮度。
- 大型单位建议同机位约 68–72 px，骑兵约 68–76 px。以下 48 px 条目是全员归一到同一高度的辨识压力测试，战场上还要对比三类单位的尺寸和遮挡。
- 若以后需要背视，增加一套镜头和校对，图集帧量约翻倍。四向方案可用正、背、侧三个镜头，另一侧翻转，帧量约三倍。两种方案都要重验侧脸、左右手装备、武器摆幅和事件接触点。

## 3. 动作【议】

下表帧号从 0 起，均为本动作局部帧。JSON 保存秒数和全局事件帧，接入时从 `start_frame` 换算。运行时以 `floor(t × N / duration)` 选择帧，非循环末端钳到 `N−1`。动作末尾事件在退出前处理，循环的 0 秒事件在进入和重启时处理。动作长度只描述演出；位移、击退、复活条件、冷却和碰撞由单局逻辑决定。

| 共用动作 | 帧数 | 秒 | 循环 | 事件秒 → 局部帧 | 姿势 |
|---|---:|---:|:---:|---|---|
| 待机 `idle` | 6 | .667 | 是 | — | 守军稳住装备，亡灵头随呼吸点动 |
| 行走 `walk` | 8 | .667 | 是 | `right_step` 0 → 0，`left_step` .3335 → 4 | 短腿交替。巨人重踏，巫妖以袍摆上下浮动，并可省略脚步事件；骑兵慢步用马步 |
| 攻击 `attack` | 8 | .600 | 否 | `hit` .333 → 4 | 预备、发力、回位。弓兵近身短匕，巫妖近身杖击作为共用姿势 |
| 格挡 `parry` | 8 | .650 | 否 | `block` .260 → 3 | 盾兵前推出盾；适用的无盾兵用武器或手臂 |
| 拼刀 `clash` | 4 | .350 | 否 | `contact` 0 → 0 | 接触后立即弹开 |
| 受击 `hit` | 2 | .167 | 否 | `impact` 0 → 0 | 肩和头一起后弹；强受击进倒地或击飞 |
| 倒地 `fall` | 4 | .350 | 否 | `ground_contact` .350 → 3 | 失衡、蹲塌、落地 |
| 倒地停留 `sit` | 6 | 1.000 | 是 | — | 接 `fall` 尾姿，小幅晃动 |
| 起身 `rise` | 10 | .833 | 否 | `standing` .740 → 8 | 支地、收脚、接回待机 |
| 死亡 `death` | 7 | .583 | 否 | `ground_contact` .486 → 5 | 一般单位停在倒下尾姿。骷髅散成骨堆，骑兵人马作为整套倒地 |
| 击飞 `ragdoll` | 6 | .517 | 是 | — | 蜷身转一周。世界空间抛物线和落地点由逻辑给出 |

格挡、拼刀和倒地停留随共用模板输出，单局按兵种能力选用。

| 兵种 | 专属动作 | 帧数 / 秒 / 循环 | 事件秒 → 局部帧 | 姿势与接入 |
|---|---|---|---|---|
| 普通骷髅 | 骨堆 `bone_pile` | 2 / .500 / 是 | — | 接死亡末帧。扁平肢骨、露颅、落剑留在地面 |
| 普通骷髅 | 骨堆重组 `reassemble` | 8 / .700 / 否 | `rattle` 0 → 0，`standing` .700 → 7 | 由骨堆聚拢四肢，最后握剑起身。单局逻辑按四秒条件和一次上限决定何时播放 |
| 暗影刺客 | 潜行 `sneak` | 8 / .580 / 是 | `right_step` 0 → 0，`left_step` .290 → 4 | 收刃低姿移步，可由现有显示透明度淡入。脱战 3 秒重新潜行由逻辑计时 |
| 暗影刺客 | 背刺 `backstab` | 8 / .480 / 否 | `hit` .240 → 4 | 前臂和短刃一起刺到最远，随后缩回。暴露与首击判定由逻辑处理 |
| 缝合巨人 | 横扫 `sweep` | 10 / .950 / 否 | `hit` .530 → 5 | 抬肩蓄势、平扫、跟随，命中给扇形击退 |
| 缝合巨人 | 砸墙 `wall_slam` | 12 / 1.200 / 否 | `hit` .700 → 7 | 举拳过顶、双拳下砸，事件帧对到墙或门；碎石是独立特效 |
| 巫妖 | 冥火弹 `gravefire_cast` | 10 / .900 / 否 | `release` .540 → 6 | 抬杖、聚火、杖尖向前。发射频率 3 秒，命中眩晕 1 秒由逻辑负责 |
| 弓兵 | 射击 `shoot` | 10 / .900 / 否 | `release` .540 → 6 | 搭箭、拉满、松弦。弓臂留出三角负形，可用两段弓弦分别绑定双手，发射后收回 |
| 骑兵 | 冲锋起步 `charge_start` | 8 / .640 / 否 | `charge_ready` .480 → 6 | 马颈伸、骑手前倾压枪，接奔驰 |
| 骑兵 | 冲锋奔驰 `charge` | 10 / .550 / 是 | `stride` .275 → 5 | 四蹄腾空和落蹄错开。奔跑中的实际碰撞触发下一个动作 |
| 骑兵 | 冲锋接触 `charge_impact` | 8 / .400 / 否 | `hit` 0 → 0 | 枪身和骑手在碰撞时收顿。冲锋击退结算每次只触发一次 |
| 盾兵、弓兵、骑兵 | 撤退跑 `retreat_run` | 8 / .520 / 是 | `right_step` 0 → 0，`left_step` .260 → 4 | 转向撤离点，盾放低、弓收胸前；骑兵用疾驰，事件用于蹄声。上船由场景处理 |

测试衔接时优先看攻击回待机、落地接倒地停留、起身接待机，骷髅另看死亡 → 骨堆 → 重组 → 待机。发射取杖尖或弓的画面接触点，翻转时对脚底锚点镜像。投射物、破墙、眩晕和骨堆冥火在世界空间另放。

## 4. Blender 和图集【议】

| 类别 | 模型单位 | 骨架 | 画布和默认正交尺寸 | 脚底锚点 |
|---|---|---:|---|---|
| `normal` | 人形身高 1.92 | 15 | 64×64 / 3.05 | (32, 62) |
| `large` | 人形身高 2.88 | 15 | 96×96 / 4.575 | (48, 93) |
| `mounted` | 骑手站高基准 1.92，乘骑另加鞍高 | 26 | 128×128 / 6.10 | (64, 124) |

人形由根、脊椎、头、双臂和双腿组成，手脚刚性绑定。坐骑加马体、马首、尾和四腿各两段共 11 骨，骑手和坐骑烘焙到同一个 Action。画布从一开始按单位定好，所有动作共用脚底锚点。只有落地穿地的姿势补足垂直偏移，JSON 记录 `ground_lift`。加宽画布时同时看倒地、击飞和武器伸展。舞台中按站姿高度换算世界单位，避免把每个动作都缩到一样高。

同一个网格导出两套可直接读取的图像：

- `<id>_uv.png`、`<id>_parts.png`、`<id>_uv.json` 沿用 `swordsman_uv_v1`。所有帧按 8 列排列，R/G 是部位 UV，B 是连续的法线明暗，A 是覆盖率。部位贴图沿用 4×4 分区、256 px 单图块和 2×2 外观格。JSON 继续提供全部 16 个分区描述，配方只给实际使用的分区上色，空区为透明黑。样品单外观复制到四格，色替换可用现有 `unit.gdshader` 的配置。
- `<id>_ink.png` 为普通 RGBA，帧矩形和 UV 图集共用同一份 JSON。Blender 渲出 UV 数据后离线合成墨线、两档平涂和阵营边光。单局沿用 T84 的 `Sprite3D` 贴图方式即可使用这张图。颜色已经合成，需要新配色时由配方重新烘焙。T84 临时色稿替换、行为事件接线、亮度和遮挡由 Lead/T86 在单局整合。
- `<id>.blend` 保存模型与 Action，可在 Blender 中回看。载入后默认选中 `idle`，时间轴刻度以毫秒表达。材质用于 UV 数据出图，最终色以 `_ink.png` 和两张预览为准。

## 附录 · DSH 生产手册【议】

### 准备配方

1. 给 Lead 看本兵种的侧面剪影草稿、3–4 色色板、48 px 尺寸草稿和事件姿势。草稿注明遮挡关系，弓弦留空、盾露出脸、骑兵足位与鞍位清楚。选已批准的造型和动作表。
2. 复制 `assets/specs/units/skeleton.yml`，按上表命名，放在 `assets/specs/units/<id>.yml`。使用不同 id。保留 `recipe: unit`，选择 `body`，用 `parts` 映射基础网格并给真正用到的分区写 `palette`、`rim`。普通和大型的起步上限可用 650、950 三角面，骑乘可用 1500，按装备复杂度和 Lead 验收调整。
3. 拆装备轮廓到 `pieces`。每块填写 `bone`、`part`、`points`、`depth`，可加 `offset`、`yaw`、`far`。点为围绕骨头原点的 `[x,z]` 闭合多边形，沿边依次写且末尾无需重写首点。深度沿 Y，偏移 `[x,y,z]`，负 Y 靠镜头，单位均为人形站高。一个弓或带孔的形状可拆成多个相连的简单多边形。先试剪影，再加接近像素大小的块。
4. `head.profile`、`head.stamps` 以侧面归一坐标 `[u,v]` 描述，左下是 (0,0)。轮廓用于切颅形、帽檐，`stamps` 用椭圆或多边形画眼窝、眼睛、眉线。头部区域 V=.30 以下留给同分区的手和肢体。其他分区用 `marks` 画纹章或缝线。首稿用两三道明显形，检查进到 48 px 后仍在。
5. 在 `actions` 里覆盖共用动作或加专属动作。专属动作写齐 `frames`、`duration`、`loop`、`events`，以共用动作或 `neutral` 为底。用 `tracks` 写 `[归一化时间, 值]` 从 0 到 1 的关键姿势。向量位置为身高单位，角度为度。向量通道有 `hip`、左右 `foot`、左右 `wrist`，角度通道有 `lean`、`head_tilt`、`sword`（右手）、`shield`（左手）、`tumble`。循环通道首尾相同。冲锋或撤退可用 `mount_gait: gallop`，日常马步用 `trot`。骑乘需补 `mount.parts`、可选 `seat`、`stride`、`pace`。散架可用 `scattered` 的 `[x,y,z,俯仰角]` 记录离体骨段位置，以 `spread` 在正常姿势和散架之间过渡。需要无缝衔接的动作对写入 `transitions`。
6. 配方沿用项目 YAML 子集。用空格缩进、常规映射、行内列表或行内映射，色值加引号。当前解析器支持写成多行的行内集合。布料摆动可随骨或分片修改姿势。

### 构建、检查和提交

在仓库根目录运行。需要项目版本的 Blender 与系统 Python 3；NumPy 随 Blender 提供。

```sh
# 草稿渲染、验收与预览
python3 tools/blender/batch_units.py --draft --output /tmp/unit-draft assets/specs/units/skeleton.yml

# 单件正式输出
python3 tools/blender/batch_units.py assets/specs/units/skeleton.yml

# 正式串行构建所有已入库的配方，并单件验收
python3 tools/blender/batch_units.py

# 查看固定验收结果
tools/verify/verify.sh sprites

# 窗口版 Godot 截图，任选现有素材目录中的同名文件前缀
godot --path . --log-file /tmp/unit-capture.log --script tools/blender/capture_unit.gd -- res://assets/sprites/units/skeleton/skeleton /tmp/skeleton-godot.png
```

草稿使用 2× 超采样，输出到指定目录。正式使用 8×，并保存 Blender 模型。正常结果包含 `VALIDATED <id>` 和 `UNIT PASS <id>`。成功资产进 `assets/sprites/units/<id>/`。固定验收发现 `assets/specs/units/*.yml`，所以配方及正式产物一并提交。只有终稿目录应进入仓库。窗口截图使用显式日志路径，避免 `user://logs` 的写入噪声。

逐件自检：

- 打开 `_48px.png` 对照 T84，检查待机、专属姿势和翻转。两侧装备与眼睛、阵营边光、交战朝向在深底上可读，身高符合类别。
- 打开 `_actions.png` 逐行看帧。确认脚底锚点、步态交替、循环、事件所在格、攻击回收、击飞画布、尸体尾帧。检查盾边和脸、弓弦和手、马肚下左右腿的遮挡。金色帧号表示事件格。
- 在可用图形会话运行截图命令。上排检验 Sprite3D 的墨线成品，下排检验现有 UV 着色器的兼容性。打开文件核对实际画面。截图证据随任务报告交 Lead。单局最终表现另外在可玩场景看一次。
- 读三角面、UV 分区、像素裁切和事件校验。声明的装备、装饰件应该出现在模型和预定姿势。每件通过后，在 DSH 的独立分支交配方、产物和报告。

出现失败时从单件草稿重跑。相机裁切优先收回误伸的肢体或武器；比例和装备正确时再调整 `camera.ortho` 或 `camera.foot_margin`，然后重看站姿占格。侧脸模糊就检查帽缘是否遮挡眼窝，扩大主要眼窝或把纹样移到镜头侧。颜色出错先查 YAML 色号和分区映射。帧错位就核对事件秒数映射、端点和循环姿势，按需要加帧或修关键帧。若 Godot 无图形会话，保留 Blender 两张预览与命令日志，向 Lead 提交窗口补拍项。

### 5.x 腿部造型【定】（用户 2026-11-28："小短腿本质还是倒 V 交叉"）
Lead 读了参考作的原始帧图集（本机解包文件，只看不取用），结论：
- **下半身是一整块，不是两条腿**。裤子、腿、脚连成一个圆角的"口袋"形，宽度和躯干相同，底部是两个圆脚团。
- **站立时两脚之间只有底部一个浅缺口**，深度约为身高的 6–8%，形状是圆弧（∩），**裆下没有透空的三角**。
- **迈步、弓步时只是这块整体变形**：一只脚团向前、一只向后，缺口张开成圆拱（∩ 变宽），腿始终粗、没有膝盖、没有大腿和小腿的直线，所以永远不会出现倒 V。
- **轮廓**：头约 35%，躯干约 35%，下半身约 30%；三段几乎同宽，整体是一块圆角长方。手臂也是短团。
- **表现力不靠腿**：动作靠整个身体倾斜、压低，加上武器的大块拖影。腿只负责"站稳"和"往哪边迈"。

落到我们的管线：
1. 腿模型改成**一个连体的下半身网格**（或两条粗腿外面包一层连裆的裤裙），每条腿宽度不小于躯干的一半，两腿在站姿下相互贴合。
2. 骨骼动作限制：大腿前后摆角度上限约 25°，不做明显屈膝；缺口张开时必须保持圆拱，不能露出直线腿。
3. 验收器新增"裆部透空"检查：站姿帧中，两脚缺口高度不超过身高 8%；任何帧中，下半身透空区域不得呈尖角（倒 V）。
4. 骷髅也照此处理：用破腰布和盆骨把上半段连起来，腿骨只露出脚团附近一小段，不画两根细骨。
5. 小碎步（4 帧）在此基础上做：脚团前后交替错开，缺口宽窄变化，身体整体跳步由引擎负责。
