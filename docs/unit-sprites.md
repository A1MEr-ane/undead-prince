# 基础单局小兵精灵【议】

适用范围为《基础单局 v1》第 2 节的七个兵种。设计以通过的 T84 午夜局内样张为准，Q 版阵容图用于参考骨相和装备。当前分支的样张和单局规格可从 `main` 对照读取。本文的轮廓、动作素材和播放时序交 Lead 审批，战斗判定沿用单局规格。

## 1. 公共造型【议】

- 单战区固定镜头。模型朝 +X，Blender 相机在 −Y 纯侧正交。游戏样张和验收镜头俯角 30°，画面向左时水平翻转。发射点、阵营光和处于前后的装备一起翻转。镜头侧的眼窝、眉线或兜帽开口直接投影到头部 UV。
- 人形保持 B 比例。头含盔约占身高 44%，腿含脚约 22%，脚短圆。巨人以原比例放大并用肩甲、前臂外形做横向体量。骑手站姿沿用人形比例。坐骑用圆马身、短蹄和突出的口鼻扩展轮廓。
- 以 1080p 画高下普通步兵站姿约 72 px 为读图基准。每个兵种保留 3–4 组大色，墨线约 1–2 屏幕像素。明暗分成两档。亡灵用青绿边光，守军用暖金边光。眼窝、衣缝和墨线共用深色组。夜里青绿可辨，冥火弹和眩晕特效仍占画面最高亮度。
- 同机位下巨人默认约 122 px（1.7 倍），骑乘总高默认约 119 px（1.65 倍，随鞍高调整）。验收以同一相机比例查看三类单位的尺寸与遮挡。
- 若以后需要背视，增加一套镜头和校对，图集帧量约翻倍。四向方案可用正、背、侧三个镜头，另一侧翻转，帧量约三倍。两种方案都要重验侧脸、左右手装备、武器摆幅和事件接触点。

## 3. 动作【议】

下表帧号从 0 起，均为动作局部帧。全部素材以 12 FPS 播放，表中固定事件用帧号列出。事件时间为帧号 ÷ 12，标记“末尾”的事件发生在 `duration`，并落在末格。JSON 保存事件的秒数及全局帧号，用全局帧号减 `start_frame` 得局部帧。运行时以 `floor(t × N / duration)` 选帧，非循环到尾时停在最后一帧，循环进入或跨零时处理 0 秒事件。伤害、位移和复活条件由单局逻辑决定。

| 共用动作 | 帧数 | 循环 | 事件局部帧 | 姿势 |
|---|---:|:---:|---|---|
| 待机 `idle` | 6 | 是 | — | 稳住装备，轻微呼吸点头 |
| 行走 `walk` | 4 | 是 | `right_step` 0，`left_step` 2 | 上身锁定，双足小碎步。巫妖可改为无脚步事件的漂浮 |
| 攻击 `attack` | 8 | 否 | `hit` 4 | 高位后摆、水平击出、下压收势 |

| 拼刀 `clash` | 4 | 否 | `contact` 0 | 接触后立即弹开 |
| 轻受击 `hit_light` | 4 | 否 | `impact` 0 | 头肩短促后仰 |
| 重受击 `hit_heavy` | 7 | 否 | `impact` 1 | 整个身体后仰，后脚撤半步 |

## 4. Blender 和图集【议】

| 类别 | 模型单位 | 骨架 | 画布和默认正交尺寸 | 脚底锚点 |
|---|---|---:|---|---|
| `normal` | 人形身高 1.92 | 18 | 128×128 / 3.05 | (64, 124) |
| `large` | 人形身高 3.264 | 18 | 128×128 / 5.185 | (64, 124) |
| `mounted` | 骑手站高 1.92，默认鞍高 1.248 | 29 | 128×128 / 5.05 | (64, 124) |

人形保留根、脊椎、头、双臂和双腿的姿势骨。连体腿网格由腰口、前脚团和后脚团三个变形骨驱动，两个脚团沿脚位轨道交替前后，脚团间始终连有一段圆弧。坐骑加马体、马首、尾和四腿各两段共 11 骨，骑手和坐骑烘焙到同一个 Action。所有动作共用脚底锚点，画布内保持透明边距。只有落地穿地的姿势补足垂直偏移，JSON 记录 `ground_lift`。加宽画布时同时看倒地、击飞和武器伸展。三张预览按同一比例 `72 / 1.92` 像素每模型单位出图，`presentation` 记录模型比例和图集比例。舞台按站姿像素高度换算 `pixel_size`，同一兵种的全部动作共用该值。

同一个网格导出两套可直接读取的图像：

- `<id>_uv.png`、`<id>_parts.png`、`<id>_uv.json` 沿用 `swordsman_uv_v1`。所有帧按 8 列排列，R/G 是部位 UV，B 是连续的法线明暗，A 是覆盖率。部位贴图沿用 4×4 分区、256 px 单图块和 2×2 外观格。JSON 继续提供全部 16 个分区描述，配方只给实际使用的分区上色，空区为透明黑。样品单外观复制到四格，色替换可用现有 `unit.gdshader` 的配置。
- `<id>_ink.png` 为普通 RGBA，帧矩形和 UV 图集共用同一份 JSON。Blender 渲出 UV 数据后离线合成墨线、两档平涂和阵营边光。单局沿用 T84 的 `Sprite3D` 贴图方式即可使用这张图。颜色已经合成，需要新配色时由配方重新烘焙。T84 临时色稿替换、行为事件接线、亮度和遮挡由 Lead/T86 在单局整合。
- `<id>.blend` 保存模型与 Action，可在 Blender 中回看。载入后默认选中 `idle`，时间轴刻度以毫秒表达。材质用于 UV 数据出图，最终色以 `_ink.png` 和三张预览为准。

## 附录 · DSH 生产手册【议】

### 准备配方

1. 给 Lead 看侧面剪影、3–4 色色板、实际尺寸草稿和事件姿势。用 72 px 步兵作同机位参照，摆上巨人和骑兵检查高度与遮挡。
2. 从 `assets/specs/units/zombie.yml` 或 `shadow_assassin.yml` 取结构，按表命名为 `assets/specs/units/<id>.yml`。选择 `body` 和 `body_style`（一般兵省略，另有露骨 `bones` 与贴身衣 `fitted`）。`parts` 映射基础网格，`palette` 只填实际分区，`rim` 给阵营边光。普通、大型、骑乘的三角面预算可从 650、950、1500 起。单侧破袖可用 `parts.forearm_l` 或 `parts.forearm_r` 指定露出的材质。
3. `pieces` 每片填 `bone`、`part`、`points`、`depth`，可加 `offset`、`yaw`、`far`。点用围绕骨头原点的 `[x,z]` 排成闭合轮廓，末尾省略重复点。深度沿 Y，负 Y 靠镜头，位置和长度用站高作单位。孔洞可用几片相接的简单多边形围出。
4. `head.profile` 和 `head.stamps` 用左下为 (0,0) 的归一化侧面坐标画形和眼睛。头部占分区 V=.30 以上，共用分区的手及肢体占下方。其他纹样用 `marks`。降低次要纹样对比，先确认眼窝、补片和刀刃在实际尺寸仍能看见。
5. 在 `actions` 中覆盖模板或加专属动作。新动作填 `frames`、`loop`、`events`，`duration` 可省略，默认帧数 ÷ 12。用 `pose` 选择模板或 `neutral`。每条 `tracks` 从归一化时间 0 写到 1，循环的首尾值相同。髋、手腕、脚的向量用站高作单位，`lean`、`head_tilt`、`sword`（右手）、`shield`（左手）、`tumble` 用度数。压扁可以覆盖 `vertical_scale`，散架用 `spread` 和 `scattered` 的 `[x,y,z,俯仰角]`。需无缝的动作对写进 `transitions`。
6. 行走继承四帧模板，保留 0 秒右脚、2/12 秒左脚两个步点。潜行沿用 `pose: walk`，可用常量轨道压低躯干和持刃位。骑手和马共同烘焙，日常走路用默认 `shuffle`，冲锋可用 `mount_gait: gallop`。巫妖漂浮可用 `pose: neutral` 为底，加循环髋位轨道及空 `events`。陆兵撤退跑以 `neutral` 写独立步态。配方用常规映射和行内列表，颜色加引号。
7. 连帽紧身衣可参考刺客的 `head.garment`。每行按站高填 `[高度, 后缘, 前缘, 半深]`，从腰口到帽尖排列，中间包含下巴高度。头、衣身、领和腰共用一个部位。肩颈一带由头与脊椎共同驱动，开口用 `head.stamps` 绘制。逐帧检查扭头和潜行时的肩线与轮廓。
8. 需要刀离手时，将刀身和刀柄都绑到 `weapon_r`，在 `scattered.weapon_r` 写地面位置和角度。`spread` 为 0 时随右手，1 时留在目标位置。检查落刀、撑地、拾刀和最后一帧接待机。

### 弓兵与缝合巨人配方注意事项

- `archer.yml` 的弓臂连成一整根长弧，两端以细弦相连，弓臂与弦之间留出看得见的空形。搭箭时箭尾碰弦，满弓时拉弦手到耳边，放箭事件所在帧伸弓回弹并交给投射物。侧视与水平翻转都核对箭头方向、持弓手和耳侧拉弦手。
- `stitched_giant.yml` 用 `body: large`，站姿约 1.7 倍步兵，保留大头、短腿和宽脚。通过横向肩线和两块粗前臂拉开轮廓，前额与近侧前臂各留清楚的缝线，补片用可辨的邻近色。上举砸墙和齐肩横扫各看一个事件格，拳头与脸留出空隙。预览同时摆普通丧尸看体量。

用 `actions.<动作>.bone_scale` 给指定骨骼写沿骨长的倍率。每条轨道由 `[归一化时间, 倍率]` 组成，倍率须为正数，两个端点分别为 0 和 1，循环动作首尾倍率相同。关键帧间平滑插值。肢体保持原宽度，下游关节随骨长变化移动。省略轨道时该骨使用原长。以下为缝合巨人的砸墙用法，放到该动作的 `tracks` 同级。

```yaml
bone_scale:
  upper_arm_l: [[0, 1], [0.30, 1.3], [0.5833, 1.3], [1, 1]]
  forearm_l: [[0, 1], [0.30, 1.3], [0.5833, 1.3], [1, 1]]
  upper_arm_r: [[0, 1], [0.30, 1.3], [0.5833, 1.3], [1, 1]]
  forearm_r: [[0, 1], [0.30, 1.3], [0.5833, 1.3], [1, 1]]
```

在配方顶层加 `bow_string`。删除 `pieces` 里的旧直弦，保留整根弓臂。两个 `tips` 对齐弓臂的下端和上端，`draw_offset` 对齐拉弦手旁的箭尾。它们是待机姿势中相对各自骨头原点的 `[x,y,z]` 偏移，以站高为单位，负 Y 靠镜头。用 `palette` 中的 `part` 给弦上色，`width` 为站高的比例，按实际尺寸对照其他细线。可用 `nocked_pieces` 列出绑定在 `draw_bone` 上的箭杆、箭头及尾羽，使它们只在搭箭至放箭前可见。

```yaml
bow_string:
  bow_bone: hand_l
  tips: [[-0.017, -0.010, -0.389], [-0.017, -0.010, 0.390]]
  draw_bone: hand_r
  draw_offset: [0, -0.045, 0.012]
  part: cloth_trim
  width: 0.013
  nocked_pieces: [nock_arrow, arrow_head, arrow_fletch]
actions:
  shoot:
    frames: 10
    loop: false
    pose: neutral
    events: {nock: 0.1666666666666667, release: 0.5}
    bow_draw: [nock, release]
```

`bow_draw` 引用当前动作中两个按时间排列的事件，`events` 用秒数。搭箭帧起，弦的中点跟随拉弦手，放箭帧起回到两弓梢之间的中点。其余动作始终为直弦。用手腕和手部角度轨道对齐搭箭的位置、满弓朝向和放箭后的收手动作。

### 构建、检查和提交

在仓库根目录运行。需要项目版本的 Blender 与系统 Python 3，NumPy 随 Blender 提供。

```sh
# 单件草稿
python3 tools/blender/batch_units.py --draft --output /tmp/unit-draft assets/specs/units/zombie.yml

# 单件正式输出或批量重建
python3 tools/blender/batch_units.py assets/specs/units/zombie.yml
python3 tools/blender/batch_units.py
tools/verify/verify.sh sprites

# Godot 图形会话截图
godot --path . --log-file /tmp/unit-capture.log --script tools/blender/capture_unit.gd -- res://assets/sprites/units/zombie/zombie /tmp/zombie-godot.png
```

草稿用 2× 超采样（256 px），正式用 4×（512 px）并保存 Blender 模型。正式墨线在普通格约 2 个图集像素，预览约 1–2 个屏幕像素。大型和骑乘按同一屏幕粗细换算。成功资产进 `assets/sprites/units/<id>/`，输出含 `VALIDATED <id>` 和 `UNIT PASS <id>`。固定验收遍历已入库的配方，提交时把正式图集、清单、三张预览和配方一起交付。

- 按 100% 缩放打开 `_in_game.png`，对照 T84 暗背景检查待机、走路、专属姿势和翻转。检查头、两只脚、武器和边光，骑兵要读出骑手、马首和短蹄。
- 在 `_actions.png` 取预备、事件、收势三格，临时将角色填成单色，按原脚底线并排。预备看武器是否抬起或后拉，事件看手或道具是否到接触方向的最远点、重心是否移到前脚，收势看道具与躯干是否换角度、步幅是否收回。单色轮廓足以认出顺序后，再核对面部、装备和事件格（金色帧号）。检查攻击回待机、循环闭合和步点的两次落脚。
- 在 `_reactions.png` 对比第一次反应、最大幅度和尾姿。轻击看头肩，重击看后仰撤步，击退看双足离地和张臂，箭伤看前弯扶胸，眩晕看双脚定住而头身摆动。并排比较三种死亡尾格和倒地、起身的衔接。
- 查看验收输出 `proportions`。用站姿网格最高点与脚底测身高，用头部网格（含盔、兜帽）测头高，用大腿根关节到脚底测腿。骑手以站姿还原测量。头高目标为 1/2.3，腿长为 .22，比例各容许 ±.03。再读裁切、UV、步态锁定、事件与循环的结果。
- 查看 `crotch`。验收器沿脚底局部平面投影下半身，逐帧检查缺口轮廓。站姿最大缺口深度为身高 8%，迈步和弓步的缺口保持圆拱。连体腿自带脚团和裆部，配方用脚位轨道摆造型。露骨配方用 `belt` 给上段裤布上色，`legs` 给脚团上缘上色，`boots` 给脚团着色。
- 运行 Godot 截图命令，上排看 `Sprite3D` 墨线图，下排看 UV 着色器。截图随报告给 Lead。单局里另查场景遮挡、镜头和演出接线。

裁切时先核对误伸的肢体或武器，再检查 `camera.ortho` 和脚底留白 `camera.foot_margin`。事件帧看错位时先对照秒数、端点和循环姿势。图形会话不可用时交三张 Blender 预览和日志，由 Lead 补拍。需要改精灵读取、着色器或共用模板，或达到任务卡自修上限时，带配方、失败命令和复现图交回 Lead。

### 5.x 腿部造型【定】（用户 2026-11-28："小短腿本质还是倒 V 交叉"）
Lead 读了参考作的原始帧图集（本机解包文件，只看不取用），结论：
- **下半身是一整块，不是两条腿**。裤子、腿、脚连成一个圆角的"口袋"形，宽度和躯干相同，底部是两个圆脚团。
- **站立时两脚之间只有底部一个浅缺口**，深度约为身高的 6–8%，形状是圆弧（∩），**裆下没有透空的三角**。
- **迈步、弓步时只是这块整体变形**：一只脚团向前、一只向后，缺口张开成圆拱（∩ 变宽），腿始终粗、没有膝盖、没有大腿和小腿的直线，所以永远不会出现倒 V。
- **轮廓**：头约 35%，躯干约 35%，下半身约 30%；三段几乎同宽，整体是一块圆角长方。手臂也是短团。
- **表现力不靠腿**：动作靠整个身体倾斜、压低，加上武器的大块拖影。腿只负责"站稳"和"往哪边迈"。

落到我们的管线：
1. 腿模型改成**一个连体的下半身网格**（或两条粗腿外面包一层连裆的裤裙），每条腿宽度不小于躯干的一半，两腿在站姿下相互贴合。
2. 骨骼动作限制：大腿前后摆角度上限约 25°，不做明显屈膝；缺口张开时必须保持圆拱，不能露出直线腿。
3. 验收器新增"裆部透空"检查：站姿帧中，两脚缺口高度不超过身高 8%；任何帧中，下半身透空区域不得呈尖角（倒 V）。
4. 骷髅也照此处理：用破腰布和盆骨把上半段连起来，腿骨只露出脚团附近一小段，不画两根细骨。
5. 小碎步（4 帧）在此基础上做：脚团前后交替错开，缺口宽窄变化，身体整体跳步由引擎负责。

### 5.z 暗影刺客：兜帽和衣服连体【定】（用户 2026-11-28）
