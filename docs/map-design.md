## 1. 两层地图
| 层 | 是什么 | 现状 |
|---|---|---|
| 远征航图 | 王冠海的地点和航线，一局选一条航路去王都 | 已实现第一阶段（T28/T29）：39 个地点、难度颜色、首领据点 |
| 攻城战场 | 每个战斗地点的一张夜战地图 | 灰盒原型 A（T67）已有一张中型图 |

## 2. 远征航图的修订【议】
- **定位改成"沿航道突破"**：攻下一个地点，只是打开下一段航道，不经营领土。天亮前舰队沉回水下，继续前进（见 world-r2 第 4 节）。
- **一局的长度**：每场攻城加上部署和观察，约 6–8 分钟，所以每局改为 5–7 场攻城，再加剧情地点。之前定的 6–9 场下调。
- **难度规则保留**（路越短越难），新增两类信息：
  - **战场规模**：小、中、大三档，在节点上用图标表示。
  - **守军构成提示**：例如"弓兵多""骑兵预备队""城墙完整"，让玩家按自己的构筑选路。
- **首领据点不变**：
  - 锁海之门（休）
  - 盐市港（罗德里克）
  - 万谷仓（阿格尼丝）
  - 苍白圣堂（安塞姆）
  - 永昼王城（沃尔特）
- **航图上体现冬恩**：每个地点标注它从王都分到多少冬恩，例如"圣火龛 ×3""无龛"。玩家一路看到全国的不均，这是终止永昼时的情感铺垫。
- **canon 的 39 个节点和 75 条边**：等用户决定地图是否重新设计。数据层支持整体替换。

## 3. 攻城战场的规模递进【议】
| 阶段 | 典型地点 | 战场规模 | 结构 |
|---|---|---|---|
| 前期（第 1–2 场） | 渔村、灯塔、哨站 | 小：2–3 个战区，1 个主据点 | 一条主路加一条侧路，没有城墙或只有木栅 |
| 中期（第 3–5 场） | 港口、城镇、修道院 | 中：4 个战区 | 城墙、城门、高地、山洞，相当于原型 A |
| 后期（首领、王都） | 要塞、大城 | 大：5–6 个战区，两道防线 | 外城、内城、主堡、多个登陆点 |

规模的增长体现在更多有效路线、防御纵深和守军组织，不是同比例放大。**用战术时间定标，不用面积**，每张图验收时都要测：
- 每条路线的接敌时间
- 抵达主据点的时间
- 守军各条增援路线的行军时间
- 破墙耗时
- 冥火从用完到能再投入一波有效兵力的时间

这几个时间要互相错开，才会出现可以利用的空档。具体目标值由原型数据（T68）决定。

## 4. 战场的构成元素
| 元素 | 规则 | 来源 |
|---|---|---|
| 自然地形 | 没有血量，不可破坏；决定通路、高差、交战宽度 | 【定】 |
| 城墙、城门 | 人工结构，可以局部破开；哪些墙段可破由关卡设定 | 【定】方向，细则待定 |
| 大路、小路 | 只体现在宽度和距离上，不加速度加成 | 【定】方向 |
| 山洞、密道 | 有入口和出口，转移要花时间；谁能用由关卡设定 | 候选 |
| 部署区 | 默认只有登陆滩；占领战区后是否开放新的部署点，待原型验证 | 待定 |
| 主据点 | 攻占它，守军就坐船撤离；地图上必须有守军的港口和船 | 【定】 |
| 守军驻地 | 战区、预备队营地、高地阵地 | 原型 A |
| 冬恩设施 | 圣火龛、教堂。只是叙事装饰，不参与玩法 | 【议】 |

## 5. 战场原型（按地区套件换皮）
| 原型 | 战术特点 | 适合的地区 |
|---|---|---|
| 海岸村落 | 多登陆点、开阔，守军少但会叫援军 | 灰潮外岛 |
| 灯塔海岬 | 狭长坡道、高地，单一主线加悬崖侧路 | 灰潮、引航水域 |
| 河渡口 | 桥是瓶颈，浅滩可以涉水绕行 | 金穗三角洲 |
| 港口城镇 | 码头登陆、街巷分流、城墙、守军港口 | 灰潮、金穗 |
| 沼泽圣堂 | 浅水减速、钟楼高地、墓园迷道 | 盐沼海缘 |
| 要塞关口 | 双塔、铁链、两道防线 | 松卫边境（锁海之门） |
| 王都 | 外城、内城、宫城三层；永昼之日照得通明，但仍是自然夜晚 | 永昼盆地 |

- **王都夜战的特色**【议】：
  - 人造光不算白天，亡灵照样能战斗。
  - 但城里被照得一片通明，守军的视线和弓兵射程更好，亡灵失去夜色的掩护。
  - 暗影刺客在王都里潜行会更难，除非先拿下秘印相关的地点，让一片城区暗下来。
  - 这样王都战既符合"只能夜战"，又和永昼形成对抗。

## 6. 生产方式【议】
1. 先手工搭战术拓扑（灰盒），每个原型 1 张，验证好玩之后再进入美术。
2. 美术用"模块网格 + 地区套件 + 地标预制件"（FLEET_ART_TECH_DECISION 第 5 节）。地标只给首领据点和关键剧情地点。
3. 同一个原型在不同地点换参数：守军构成、哪段墙可破、山洞开不开、登陆点位置。这样少量战场原型就能覆盖整张航图。
4. 半程序化生成（换参数、换布局）等原型稳定后再做，不做完全随机的城镇生成器。

## 7. 镜头：战区固定视角加总览切换【用户提出的主方案，待 T70 验证】
- 不做四个朝向。玩家在地图上切换战场的不同区域，每个区域只有一个固定的总览视角；另有总览图显示全局。
- **对地图设计的影响**（这个方案成立的前提）：
  - 每个战区按它的机位设计，像一幅立体的场景画：关键路线、城墙、高地、山洞口都要朝向镜头。高的建筑放在画面后方，避免挡住战场。
  - 战区之间的边界要清楚，交战尽量发生在某个战区之内，跨战区的战斗靠总览图和提醒来补。
  - 战区数量和尺度：小战场 2–3 个，大战场 5–6 个，见第 3 节。
- **对美术的好处**：
  - 每个战区只从一个角度看，建筑背面、遮挡剪影、旋转时的精灵翻面闪烁这些问题都没了。
  - 地标可以按构图精心布置，更接近"微缩场景画"的质感。
  - FLEET_ART_TECH_DECISION 里为 360° 设计的部分（翻转过渡、屋顶淡出）降为可选。
- **风险**：
  - 5 分钟里注意力被切成几块，可能错过别处的变化。靠跨战区提醒和总览图弥补。
  - 战区边界附近的战斗会被切开。
  - T70 会对比这两点。
