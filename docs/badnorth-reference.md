# Bad North 技术拆解（只记录设计思路，不含代码）

来源：用户本地解包的 Bad North: Jotunn Edition 2.00.5。本文只总结机制和做法。
禁止把原代码或素材复制进本工程。

标注：【确认】= 代码或资源里能直接看到；【推断】= 有证据支撑，但没有完全核实。

## 平台
- 【确认】Unity 2018.4，C#。输入用 Rewired，音频用 Fabric 中间件，本地化用 I2；另有 Steam、GOG、Discord 平台接口和游戏内调试控制台
- 【确认】代码分两块：岛屿生成（WFC：模块、槽位、转角、约束传播）和玩法（弹道、战役生成、英雄生成、袭击编排、脚本动画、流场寻路、升级、UI）

## 小兵表现
- 【确认】身体是 2D 帧动画精灵，始终朝向镜头，左右翻转，只有一个侧面
- 【确认】帧数：剑盾兵 71、单手武器 58、双手武器 55、弓手 37（每个兵种全部动作的总帧数）
- 【确认】盾牌等挂件挂在单独的节点上，由动画片段同时控制
- 【确认】全游戏 102 个动画片段。每个兵种大约包括：待机、走、跑、攻击、拼刀、格挡、摔倒、爬起、翻滚、死亡、坐、投掷、跳劈起跳和落地
- 【推断】精灵颜色是部位编码（图集呈红绿色块），着色器查"部位贴图"上色；部位贴图按等级分民兵、老兵、金、钢等，所以升级换装不用重画帧
- 【确认】血量写入颜色的一个通道，着色器据此表现受伤

## 移动
- 【确认】一步一跳：每一步从起点插值到落点，步长时长由距离和速度算出
- 【确认】走路动画的播放进度和步伐进度绑定，左右脚交替，所以不会滑步
- 【确认】每一步触发一次脚步声，步子够大会扬起尘土
- 【确认】影子贴合地形法线；草地浓密程度作为参数参与表现（作用【推断】为脚陷入草里）

## 行为与战斗
- 【确认】分层状态树：子状态可以设为互斥；各个能力组件把自己的状态挂到树上
- 【确认】决策按 8Hz 节拍进行，每个个体的相位随机错开
- 【确认】相邻队友之间体力会互相拉向平均值
- 【确认】拼刀：双方同时出手时进入拼刀，扣体力；体力还有剩才继续进攻
- 【确认】威慑：靠近持刃的敌人会被施加威慑，距离越近越强
- 【确认】冲击累积：超过随机阈值就滑退，超过更高的随机阈值就摔倒，倒地时长也随机
- 【确认】击飞时翻滚动画从随机帧开始，落地后有爬起动画
- 【确认】尸体朝向贴合地面并加随机偏转，由专门的尸体管理器处理
- 【确认】弓箭冷却 ±20% 随机，射击方向有散布，大小由小队设定
- 【确认】每个兵种一个小队协调器（例如枪兵整队举枪或放平）；小队目标点周围生成站位分配给个体
- 【确认】在三角网格上用流场寻路

## 素材规模
- 【确认】988 个网格、2,034 个精灵、102 个动画片段、23 个动画控制器、544 个音频、95 个着色器
- 【确认】英雄肖像由头发、鼻子、耳朵、眼睑、王冠条纹等部件拼合生成

## 对本项目的含义
1. 采用"3D 地形 + 2D 朝向镜头的小兵 + 部位换色"，帧数少，换皮成本低
2. 原型优先实现：一步一跳移动、动画与步伐同步、错开的决策节拍、冲击累积与随机阈值、翻滚从随机帧开始、相邻体力共享
3. 新增需求：进攻方视角下，守方需要自己的小队协调器（弓手占高地、枪阵守隘口、警钟增援），沿用"小队协调器 + 个体状态树"两层结构
4. 亡魂将领肖像可以参考部件拼合的思路来生成
