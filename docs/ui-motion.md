# UI 与转场：什么是"高级"，以及我们怎么做（2026-11-25）

标注：【定】= 用户决定；【议】= Claude 的设计判断。

- 【定】用户 2026-11-25：不要把用户给的图片当样张；自己判断什么高级好看。UI 和转场、UI 动画学习 Hades 2 的风格。
- 本文取代 `docs/art-style.md` 第 2 节（UI 方向）。`art/ui/` 现有的 UI 套件（T35）按本文重新评估，结论见第 4 节。
- 关于 Hades 2 的描述来自 Claude 对这款游戏的了解，属于印象，没有逐帧核对。下一步可以录屏逐帧量时长，再校准第 3 节的数值。

## 1. 我对"高级"的判断【议】
1. **克制**。一屏只有一个主角，其余都退后。装饰集中在少数位置：框角、标题、选中态。不要每条边都铺铆钉、绳子和钟。
2. **材质统一，只有一种语言**。全游戏的 UI 都是"深墨蓝的漆面，加一条细金线"。金属只在需要强调时出现：按钮按下、稀有度、首领。现在的套件同时用了锻铁、黄铜、绳索、铆钉、钟五种材质，所以显得廉价。
3. **大面积的安静，加小面积的精确**。大块深色留白，细节只做在 1–2 像素的金线、纹章和字上。高级感来自细节的精度，不是数量。
4. **暗不是黑**。底色用带蓝调的墨色，配一点纸张或漆面的颗粒。光只给可以交互的东西和角色的脸。
5. **字体是第一装饰**。
   - 中文标题用有笔锋的宋体或楷体系，字距放开一点，配合手绘的大字。
   - 正文用干净的黑体。
   - 拉丁字母（结局名、兵种标签）用窄体的衬线大写。
   - 一屏最多两种字体，三个字号。
6. **动效有目的**。每个动画都要回答"它告诉玩家什么"。进场说明"新东西出现了"，悬停说明"可以选"，确认说明"已生效"。动画要快、有分量、能被打断，不让玩家等。
7. **声音和动效一起设计**。每个关键动作都配声音：卡片入场、悬停、确认、钟声转场。没有声音的动效显得空。
8. **文字不压在画上**（用户已定：结局插画不放字）。所有界面同样遵守：信息放在面板里，插画保持干净。

## 2. 从 Hades 2 学什么（原则，不复制具体设计）【议】
| 观察到的做法 | 背后的原则 | 我们的对应 |
|---|---|---|
| 神明出场时，大幅立绘从侧面滑入，盖在暗化的房间上，同时说一句台词 | 给奖励的人比奖励本身先出场，奖励因此有人格 | 旧部给增益时，先出半身像加一句台词，再出卡片 |
| 三张祝福卡依次弹出，稍微过冲再回位；稀有度有不同的光效 | 依次出现制造期待；回弹给出重量感 | 卡片间隔 60 毫秒依次进场，带回弹；稀有度用边光的颜色和流光区分 |
| 悬停时卡片放大、提亮，其余卡片变暗 | 焦点永远只有一个 | 悬停放大 1.04 倍，未选的卡压暗 35% |
| 选定后闪光，卡片收进 HUD 的位置 | 让玩家看见"东西去了哪里" | 选中的卡化成一道光，飞向屏幕下方的槽位图标 |
| 对话时说话的人亮，听的人暗 | 层级靠明度，不靠框 | 两侧半身像：说话者亮度 100%，另一侧 55% 并稍微后退 |
| 房间之间的转场是全屏的手绘遮罩，不是普通淡入淡出 | 转场是世界观的一部分 | 我们的转场用**涨潮**（墨色海水漫过屏幕）和**钟声**（一圈声波扫过） |
| 死亡后有专门的画面和停顿，然后回到据点 | 失败是故事的一部分，要隆重 | 败北时战场褪色、钟声响起、渡魂人的提灯从黑暗里亮起，再切回沉钟湾 |
| HUD 很少，主要信息靠角色和场景本身表达 | 战斗时注意力在场上 | 战斗 HUD 只有部队卡和冥火条，其他信息在暂停时才出现 |

## 3. 动效规格【议，原型后校准】
### 3.1 通用参数
| 项目 | 数值 |
|---|---|
| 进场 | 180–260 毫秒，回弹缓出（过冲 6–10%） |
| 退场 | 120–160 毫秒，缓入；比进场快 |
| 依次进场的间隔 | 50–70 毫秒 |
| 悬停 | 90 毫秒，放大 1.04 倍，提亮 15%，边光加强 |
| 确认 | 先压缩到 0.96 倍（60 毫秒），再弹回并闪光（120 毫秒）；配声音 |
| 全屏转场 | 550–800 毫秒，中间留 100 毫秒全遮住，用来切换场景 |
| 可跳过 | 所有超过 300 毫秒的演出，点击都能直接跳到结尾状态 |
| 待机 | 选择界面上，边光有很慢的呼吸（4 秒一个周期，亮度变化 ±8%）；冥火有轻微飘动 |

### 3.2 关键界面的演出
1. **增益选择**：
   - 背景压暗到 40%。
   - 旧部半身像从左侧滑入（220 毫秒），台词逐字出现。
   - 三张卡依次从下方升起（间隔 60 毫秒，带回弹）。
   - 悬停焦点；确认后卡片化光，飞向槽位，同时该旧部的辅色在屏幕边缘闪一下。
2. **对话**：
   - 半身像从各自一侧滑入。换人说话时，明度在 150 毫秒内交叉过渡。
   - 表情切换用 80 毫秒的交叉淡化，不做位移。
   - 对话框在底部，名牌是旧部的辅色。
3. **航海图出航**：
   - 选定航线后，金线沿航路从当前点流向目标点（400 毫秒）。
   - 船形标记沿线滑过去。
   - 然后转"涨潮"：墨色海水从下往上漫过屏幕（600 毫秒），完全遮住后切入登陆部署。
4. **登陆开场**：
   - 海水退去，露出岛屿，镜头从高处推近到战斗距离（800 毫秒，可跳过）。
   - 地点名用大字淡入、停留 1 秒、淡出。只有这一处允许文字短暂压在场景上，而且出现在天空或海面上，不压在主体上。
5. **战斗胜利**：时间放慢 0.3 秒，王旗换成碎王冠军旗，奖励在旗下方升起。
6. **败北与回溯**：
   - 时间放慢，画面去饱和，中心以外渐暗。
   - 一声钟响，声波扫过屏幕。
   - 全黑 0.4 秒。
   - 渡魂人的提灯在黑暗中亮起，配一句台词。
   - 从提灯的光里展开沉钟湾据点。
7. **结局**：
   - 全屏插画无字，镜头极慢地推近（20 秒，推近 3%）。
   - 点击或等待后，插画压暗，结局名和尾声文字才单独出现。
   - 最后渡魂人说一句台词，然后回溯。

### 3.3 转场的统一母题
全游戏只用三种转场，各有含义：
- **涨潮**：空间移动，例如出航、登陆、返航。
- **钟声**：时间和命运，例如败北、回溯、阶段推进。
- **提灯**：渡魂人介入，例如据点开场、真结局。

不使用普通的黑场淡入淡出，也不用通用的擦除效果。

## 4. 对现有 UI 套件（T35）的评估
- **问题**：
  - 铆钉、绳索、钟、锻铁、黄铜同时出现，每条边都在装饰，读起来像通用的奇幻手游。
  - 按钮的斜切角加厚边框，分量太重。
  - 对话框比内容还抢眼。
- **保留**：深墨蓝底色、细金线、钟和缆绳作为母题。母题每屏最多出现一次，例如名牌上一个小钟，或者分隔线中间一个绳结。
- **改法**：
  - 面板改为无边框的深色漆面，只在上下各压一条 1 像素金线，框角加一个小纹样。
  - 按钮平时只有文字加一条下划金线；悬停时出现边光；按下时出现实体底。
  - 增益卡框：卡面以插画为主，框只是一圈细线加旧部的辅色边光；稀有度体现在流光和角标上，不靠更厚的框。
- **结论**：T35 的 UI 素材不作为最终素材，只保留据点场景构图作参考。UI 素材按本文重新出提示词，等动效原型验证完再生成。
